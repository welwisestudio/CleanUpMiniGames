# Сборка и передача

Когда игра уже создана, после каждого промпта пересобирай dist и обновляй его preview на localhost. Проверь, что ссылка открывает именно свежую сборку, и сообщи номер/время сборки. Это правило показа результата сотруднику, а не требование каждый раз публиковать игру на внешний хостинг. До финального этапа используется dev-адаптер платформы, после него — YouTube-профиль.

## Воспроизводимость

Зафиксируй package-lock, версии Node и инструментов, команды разработки/сборки/preview и Python-зависимости обработки ассетов. Для существующего lockfile используй `npm ci`. Не обновляй зависимости одновременно с правкой визуала без необходимости.

В ASMR зафиксированы Phaser 3.90.0, Vite 7.3.6 и Playwright 1.63.0; диапазоны package.json отличаются от фактически разрешённых версий lockfile. Для Vite 7 нужен совместимый Node, минимум 20.19+ или 22.12+ по [официальному руководству Vite](https://vite.dev/guide/). Версии — воспроизводимый пример, не заявление, что это последние выпуски.

## Команды, которые AI должен создать в новой игре

```text
npm run dev              локальная разработка
npm run build            production-профиль выбранной платформы
npm run preview          проверка dist через HTTP
npm test                 основные автоматические проверки
npm run package          проверенный ZIP
npm run build:original   сборка с исходными runtime-ассетами без оптимизации
```

Это ожидаемые интерфейсы нового проекта. В папке инструкций package.json отсутствует, поэтому до создания игры команды запускать некуда. AI обязан описать реальные команды после реализации, а не оставить этот список как обещание.

Vite `base:'./'` помогает размещению в подпапке. Не открывай production двойным кликом по HTML через file://. Шрифты и игровые ассеты поставляются локально; для YouTube внешний SDK подключается по правилам площадки.

## Загрузка

Разделяй первый интерактивный набор и остальной контент. В ASMR menu bundle загружался первым, затем при первом запуске уровня — весь остаток, один раз за сессию. Это не per-level streaming. Для более крупной новой игры bundle на уровень может быть лучше, но требует собственного решения и тестов.

Список menu assets включает все ресурсы окон, открываемых из меню: награды, hints/skip, валюту, VIP, Daily, карточки. В ASMR после разделения загрузки сломалась иконка Skip, потому что реестр учитывал только очевидные элементы меню.

## Оптимизация без потери исходников

Сначала измерь вклад кода, изображений, аудио и шрифтов. Не пытайся сильно ужать ZIP поверх уже сжатых WebP. Удаляй из dist неиспользуемые ресурсы по реестру, сохраняя masters вне runtime.

В ASMR WebP кодировали через Pillow/libwebp, quality 82 с исключениями 88/92/original, method 6. Проверяли размеры и побайтное равенство alpha; чувствительные зернистые эффекты не перекодировали. RGB при таком режиме с потерями. «Без заметной потери» требует визуального сравнения, а не только совпадения разрешения. Параметры WebP описаны в [Pillow](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#webp).

Каждая сборка читает исходные runtime-файлы, не предыдущий dist. Cache зависит от хеша исходника, настроек и кодека. После оптимизации проверяются размеры/alpha и игровые экраны. Сохрани способ пересборки оригинала и проверь откат.

## Бюджеты

Храни отдельно: целевой внутренний бюджет, фактический initial bundle, полную распакованную сборку, ZIP, максимальный отдельный файл и требования площадки. Уменьшение ZIP не гарантирует выполнение ограничения начальной загрузки.

Исторически ASMR удалось уменьшить до 13,95 МБ ZIP и 14,99 МБ распакованного билда. После добавления аудио размер вырос; в Chat3 внутренний порог скрипта подняли с 15 до 20 миллионов байт. Это изменение бюджета, а не новое сжатие. Не называй такой результат выполнением прежней цели 15 МБ.

Текущие лимиты YouTube и метод их измерения проверяй перед сабмитом. Не используй число из старого документа как универсальный лимит всех платформ.

## Архив и handoff

В ZIP должны лежать index.html и ресурсы в ожидаемой структуре без лишней родительской папки. Проверяй каждый путь; для переносимости новых ресурсов используй `a-z`, `0-9`, дефис/подчёркивание и расширение, без пробелов. В ASMR `Nail File.ogg` попал в выходное имя и вызвал отказ проверки.

Сверь список и SHA-256 каждого файла ZIP с dist, который проходил production-тест. Не включай исходные чаты, reference masters, тестовые видео, секреты, node_modules и mock-адаптер. Зафиксируй SHA-256 самого ZIP и приложи release notes.

Релизный пакет: архив игры, версия/дата, размер и хеш, VALIDATION, известные ограничения, статус реального SDK Test Suite. «Собран» и «допущен платформой» — разные статусы.
