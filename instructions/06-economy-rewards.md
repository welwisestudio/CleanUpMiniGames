# Экономика, награды и метаигра

Не добавляй все системы ASMR автоматически. Выбирай то, что поддерживает core loop новой игры. Начни с завершения уровня, сохранения и одного rewarded-сценария; затем добавляй нужные системы.

Системы и цели монетизации задаёт геймдизайнер; AI уточняет и предлагает параметры. Здесь настраивается стартовая экономика. После масштабирования контента обязательно выполняется [финальный баланс](10-balance.md) всей игры, включая геймплей и прогрессию. До финальной интеграции SDK объявления имитирует отдельный dev-адаптер.

## Возможные модули

| Система | Ценность игроку | Что проверить |
|---|---|---|
| Hint / skip | Помощь в затруднении | Текущая стадия, отмена рекламы, расход инвентаря |
| x3 результата | Увеличение новой награды | Только один раз для конкретного результата |
| Unlock / VIP | Постоянный доступ к контенту | Next, повтор, уже открытый и пропущенный уровень |
| Daily | Повод вернуться | Граница суток, повторный claim, перезагрузка |
| Reward track / pass | Долгосрочная цель | Одно продвижение на одну принятую награду |
| Wheel / box / chest | Вариативная награда | Состав сохранён до анимации, дубль не выдаётся |
| Collection / cosmetics | Видимый постоянный прогресс | Полученный предмет действительно отображается |
| Bonus games | Дополнительная активность | Можно выйти, лимиты не обходятся перезапуском |
| Timed gift | Награда за активную игру | Пауза/реклама не увеличивают активное время |

## Поток награды

Проверить актуальность контекста → получить результат SDK → проверить уникальность операции → применить изменение к состоянию → поставить сохранение в очередь → показать анимацию. Счётчик на экране может догонять уже изменённый баланс. Перезагрузка не должна выдавать награду повторно.

В облачной модели «сразу сохранить» означает отправить/поставить запись и отслеживать подтверждение. Пока сеть не подтвердила запись, существует риск потери незаписанного изменения при закрытии процесса. Индикатор и retry нужны; анимация не является доказательством записи на сервере.

Receipt внутри клиента предотвращает повторную обработку, но не является серверной проверкой рекламного показа и не гарантирует глобальный exactly-once между несколькими устройствами. Не обещай серверно-авторитетную экономику без соответствующего сервиса.

При покупке во время полёта монет синхронизируй отображаемый баланс с истинным. Не допускай отрицательного баланса и выдачи одной покупки двумя параллельными нажатиями. После ухода со стадии поздний rewarded-ответ обрабатывается по явному правилу, а не применяет skip к случайному новому уровню.

## Модель баланса

Собери источники и траты в таблицу; вероятности должны суммироваться в 1. Для лутбокса рассчитай ожидаемую денежную награду и отдельно условную ценность предметов. Проверь цикл «купить коробку → конвертировать содержимое → купить больше коробок». Симуляция 1/3/7 дней должна включать пользователей без рекламы и с разной частотой просмотров.

ASMR после ребаланса: 25 монет за новую звезду, 75 за три; x3 добавляет 150; hint 60; skip 150; обычная rewarded-награда 100; два бесплатных наградных бонусных раунда в день. Это пример конкретной экономики, не универсальные коэффициенты. Replay без новых звёзд не выдаёт повторную основную награду.

Зафиксируй часы сброса. В ASMR daily и бонусные квоты считались по 00:00 UTC; локальная полночь сотрудника не заменяет игровое правило. Если нет доверенного времени платформы/сервера, укажи ограничения защиты от перевода часов.

Качество баланса оценивается по реальным данным: удержание, выбор rewarded, отмены, источники/траты валюты, распределение кошелька, потребление инвентаря. В ASMR расчёт модели не был доказательством оптимальности и не означал подключение аналитики.

## Ясность предложения

Укажи награду и условие до клика, дай понятный выход. Если третья временная награда становится рекламной, это должно быть видно. Исторический запрос на FOMO/«подмену кнопки» не переносится как скрытое правило шаблона. Permanent skip допускается только как явно выбранное продуктовое решение с понятным последствием; обычно мягкий отказ проще и безопаснее для прогресса игрока.
