# Графика и Higgsfield

## Правило новых проектов

Вся новая графика генерируется только в **Nano Banana 2 через Higgsfield MCP**. Подключение выполняется на шаге 0: `https://mcp.higgsfield.ai/mcp`; затем проверить авторизацию и доступ к инструментам. Если клиент требует действий пользователя, объяснить их и дождаться авторизации. Другую модель при отказе/отсутствии Nano Banana 2 не подставлять. Исторические упоминания других моделей ниже описывают ASMR и не являются разрешением использовать их в новых играх.

Для спрайтов, которым нужна прозрачность, удаляй фон отдельной операцией Higgsfield Background Remover через MCP. Это обработка готового изображения, а не замена Nano Banana 2. Проверяй доступность операции и её схему; при отсутствии сообщи ограничение, не подменяй её генерацией или локальным chroma key.

## Что подтвердилось в ASMR

Первые персонажи и инструменты были сгенерированы через Higgsfield, но обычный HTML/CSS UI не совпадал с рисованным референсом. Пользователь потребовал полностью переделать интерфейс. Были сгенерированы кнопки, счётчики, плашки, рамки, логотип, иконки и эффекты, а видимый UI перенесён в Phaser. Затем потребовались отдельные правки композиции, фона, текста и анимаций. Хорошие картинки сами по себе не исправляют плохую вёрстку.

Основная ранняя модель — запрошенная `nano_banana_2`; в результатах сервиса встречается backend `nano_banana_flash`. Более поздние premium/cleaning/dressup партии использовали `gpt_image_2_5`. Четыре обрезанных силуэта невест исправлялись встроенным imagegen. Это исторические ID, а не обещание текущей доступности.

## Порядок работы

1. Прочитай STYLE-GUIDE. Составь список ассетов с назначением, размером на экране, прозрачностью и состояниями.
2. Проверь подключение Higgsfield MCP и найди именно Nano Banana 2: описание параметров → условия/стоимость → генерация. Если подключения нет, дай шаги подключения/авторизации к `https://mcp.higgsfield.ai/mcp`. Не выдавай заглушки за результат сервиса и не выбирай другую модель.
3. Выбери/создай проект Higgsfield для этой игры. Не используй account/project IDs ASMR.
4. В Nano Banana 2 сгенерируй небольшой набор: главный объект, один инструмент, кнопку, фон. Собери один экран и проверь стиль по референсам геймдизайнера в игровом размере.
5. Зафиксируй принятый образец и используй его как визуальный reference для остальных партий.
6. Дождись завершения jobs, скачай masters, осмотри изображения. Статус submitted не означает completed.
7. Для ассетов с требованием прозрачности выполни Background Remover по процедуре ниже. Сохрани отдельный PNG с alpha, затем подготовь crop, размеры и anchors. Фоны сцен не вырезай; готовый корректный alpha повторно не обрабатывай. Проверь sprites на светлом, тёмном и игровом фоне.
8. Зарегистрируй локальные файлы и проверь их в игре. Обнови manifest, сохрани отклонённые варианты отдельно от runtime.

В истории использовались операции `models_search`, `models_get`, `create_project`, `estimate_image_cost`, `generate_image`, `generate_image_batch`, `jobs_wait`, `show_generation_by_ids`. Названия и аргументы текущего коннектора нужно получить из его схемы. Не копируй старый JSON вызова вслепую. В ходе подготовки этого шаблона генерации не запускались.

## Промпт ассета

```text
Create a production 2D game sprite for [GAME]. Use the attached approved
reference for palette, outline weight, painted materials and lighting.
Subject: [ONE OBJECT / CHARACTER STATE]. View: [FRONT / TOP / 3-QUARTER].
Canvas: [ASPECT]. The entire silhouette fits with [10-15]% clear padding.
Working point: [nozzle / tip / gripping point] at normalized [x,y].
Keep all character states aligned to [head center, feet, common canvas].
Background: plain uniform neutral background contrasting with the subject.
The background will be removed separately with Higgsfield Background Remover.
Preserve all fine silhouette details; no colored spill from the background.
No text, labels, UI, extra objects, cast shadow on the background or checkerboard.
Readable at [DISPLAY SIZE]. Deliver a complete uncropped object.
```

Не пытайся получать все возможные элементы одним огромным атласом. Для нескольких небольших предметов допустима сетка с явным порядком и большими полями. Широкое платье, сложный инструмент и главный игровой объект лучше генерировать отдельно.

## Специализированные промпты

**Рисованный UI:** «Создай согласованный набор пустых поверхностей кнопок, рамок и счётчиков. Контур [цвет/толщина], свет [направление], материал [описание]. В центре чистая зона для динамического текста. Иконки отдельными изображениями, одинаковая толщина контура. Текст и числа не запекай».

**Очистка поверхности:** «Изолированный [диван/ковёр/объект] без комнаты и фона. Полный силуэт, фиксированный ракурс. Отдельно укажи зоны обивки, стекла, пола. Базовый объект чистый: грязь и пену игра накладывает интерактивными слоями».

**Состояния персонажа:** «Один и тот же взрослый персонаж, одинаковые лицо, поза, камера, масштаб, точка головы и линия стоп. Состояния [перечень]. Вся одежда и волосы внутри кадра. Не меняй геометрию тела между состояниями».

**Ремонт обрезания:** «Сохрани личность, позу, цвета и дизайн. Восстанови только недостающий край силуэта, добавь свободные поля со всех сторон. Не оставляй вертикально срезанный край. Ровный нейтральный фон для последующего вырезания». После ремонта packer обязан приоритетно использовать исправленный master.

## Удаление фона через Higgsfield MCP

Целевой инструмент — [Higgsfield Background Remover](https://higgsfield.ai/apps/image-background-remover). На странице приложения описаны вход PNG/JPG и выход PNG с прозрачным фоном без промпта. URL страницы не является MCP endpoint; подключение остаётся `https://mcp.higgsfield.ai/mcp`.

1. В начале проекта проверь список реально опубликованных MCP tools. Ищи отдельную операцию удаления фона; `remove_background` — ориентир из описания каталога, не гарантированное имя доступного вызова. Прочитай её текущую схему, входные ссылки/ID, ограничения, стоимость и способ получения результата. Не придумывай model ID, JSON-аргументы или endpoint по URL приложения. Наличие приложения на сайте не доказывает доступность в этом клиенте.
2. Сохрани принятый исходный master без изменений. Передай именно его через поддержанный схемой способ: результат завершённой генерации либо загрузку локального файла. Используй только возвращённые сервисом media/job ID или URL; локальный путь не является публичной ссылкой. Один объект на изображении предпочтительнее атласа: мелкие отдельные элементы могут потеряться при сегментации.
3. Выполни отдельную операцию Background Remover в рамках согласованного бюджета. Не отправляй художественный промпт, если его нет в схеме. Не вызывай `generate_image` с выдуманным `model=remove_background`. Новая генерация Nano Banana 2 нужна только для согласованного исправления исходного рисунка.
4. Если операция асинхронная, сохрани её job ID и дождись завершения способом, указанным инструментом. Ошибка/таймаут не означает готовый ассет; перед повтором проверь уже созданную задачу. Скачай оригинальный результат, а не thumbnail/preview, в отдельный cutout PNG. Запиши операцию, вход, статус и выход в manifest отдельно от генерации.
5. Проверь реальную alpha: для обычного вырезанного объекта должны существовать прозрачные и непрозрачные пиксели; полностью пустой или полностью непрозрачный результат отклони. Одного наличия RGBA недостаточно. Осмотри края, волосы, кружево, отверстия и мелкие выступы на светлом, тёмном и игровом фоне. Не допускай шахматки внутри пикселей, каймы, дыр в объекте и потери деталей. Сравни силуэт, размер и положение с master.
6. Только после приёмки выполняй crop/padding, resize и runtime-экспорт. Если размер или положение изменились, зафиксируй преобразование; пересчитай pivot и рабочую точку. Состояния персонажа приводи к общему холсту и опорам, а не независимо центрируй каждый crop. Проверь alpha после экспорта и в игре.

Если инструмент не опубликован, недоступен аккаунту или завершился ошибкой, поставь `blocked`/`failed` только соответствующему этапу ассета и сообщи причину. Продолжай независимую работу. Веб-приложение по ссылке — возможный альтернативный путь, но не результат MCP; согласуй изменение способа, если оно ещё не разрешено пользователем. Не переходи незаметно на локальный flood fill, chroma key, другую модель или перерисовку объекта.

Проверено 02.10.2026: страница приложения доступна; описание MCP-каталога упоминает `remove_background` среди отдельных операций. В наборе инструментов этой сессии такой вызываемый tool отсутствует, а поиск/рекомендация моделей не дали подтверждённого маршрута удаления фона. Реальная операция, её аргументы, цена и качество на игровых ассетах не проверены. При следующем подключении проверь доступность заново.

## Подготовка ресурсов

Python + Pillow обрабатывают растровые файлы; NumPy применяется там, где нужны маски/регистрация. В ASMR использовались flood fill от края для удаления связанного фона, cyan key, удаление цветной каймы, crop с полями, ресайз Lanczos и экспорт WebP. Это исторический способ ASMR, не основной процесс новых игр. В новом процессе Python/Pillow используются после Background Remover для проверки alpha, crop/padding, ресайза и экспорта с сохранением прозрачности. Локальное удаление фона допускается только как явно согласованное исключение с записью причины в DECISIONS.

Не удаляй весь похожий цвет глобально: можно пробить дыры в зелёном роллере, одежде или белом кружеве. Проверяй alpha и полупрозрачные края. Сохраняй точку инструмента после crop: носик кувшина и головка душа должны совпадать с курсором и источником частиц.

Для интерактивной очистки нужен общий базис координат: sprite alpha ∩ маска поверхности ∩ область разрешённого действия. По нему строятся и грязь, и пена, и выборка прогресса. Нарисованная вручную маска, не привязанная к новой картинке, — частая причина грязи вне объекта.

## Приёмка партии

- Стиль совпадает с образцом; иконки читаемы в игровом масштабе.
- Нет обрезанного силуэта, случайного текста, фона-шахматки, цветной каймы.
- Варианты персонажа совмещаются, объекты на сцене стоят на опорах.
- Зафиксированы исходный размер, crop, pivot, рабочая точка, runtime key, prompt и фактическая модель.
- Для вырезанных ассетов записаны исходный master, операция удаления фона, её результат и проверка alpha; фоны сцен сохранены.
- Переэкспорт воспроизводим и не возвращает старые дефекты.

Генерация музыки и SFX через доступный тогда Higgsfield не состоялась: найденный аудиоинструмент поддерживал речь, каталог дал 504. В итоге использовали предоставленные пользователем OGG. Для нового проекта проверяй возможности сервиса, не обещай музыку лишь по наличию TTS.
