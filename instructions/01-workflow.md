# Производственный процесс

## Ответственность

Геймдизайнер приносит концепцию, Core Loop, базовые механики, концепцию первых уровней, монетизацию, видео и подписанные скриншоты. AI уточняет непонятное, фиксирует план, выполняет техническую работу и показывает варианты. После принятия основы AI может предлагать новые механики и масштабировать контент. Основное направление не меняется без решения геймдизайнера.

## Этапы и checkpoints

Нумерация совпадает с руководством сотрудника. Согласование checkpoint обязательно до перехода дальше; обычные исправления внутри этапа выполняются автономно.

| Шаг | Работа | Что показать / согласовать |
|---|---|---|
| 0 | Концепция, видео, много подписанных скриншотов; GitHub и Higgsfield MCP | CP0: бриф, понятная концепция, доступна Nano Banana 2; проверена доступность Background Remover через MCP и записаны ограничения |
| 1 | AI выводит стиль из референсов и готовит план реализации | План соответствует решениям геймдизайнера |
| 2 | Один уровень по заданной механике, Phaser, dev-адаптер | CP1: рабочий localhost, core проверен мышью/touch |
| 3–4 | Графика Nano Banana 2, вырезание спрайтов Background Remover, UI, фидбек и подсказки первого уровня | CP2: принятый визуальный и игровой эталон |
| 5–6 | Пять уровней, меню/HUD/результат и аудит интерфейса | CP3: пять уровней и весь основной UI |
| 7 | Заданная метаигра/монетизация, стартовые числа, тестовая реклама | CP4: понятные награды и траты |
| 8 | Новые темы/механики в принятой концепции, партии контента | Один образец нового типа; каждую партию согласовать |
| 9 | Полный контент и аудио | CP5: готовая игра со звуком до общего баланса |
| 10 | Геймплейный, прогрессионный и экономический баланс | CP6: сравнение до/после и живой плейтест |
| 11 | Настоящий YouTube SDK через сменный адаптер | Контракты/CSP/облако/mute/реклама и тест в YouTube |
| 12 | Финальная сборка, проверка баланса после SDK, ZIP | CP7: приёмка релиза, отчёт, версия в GitHub |

Слой платформы проектируется заранее, но реальная интеграция YouTube выполняется только на шаге 11. До него нет YouTube bootstrap и настоящих объявлений; работает отдельный dev-адаптер. Подключение Higgsfield MCP на шаге 0 относится к инструменту производства графики и не является игровым SDK.

## Результат каждого промпта

Когда игра уже существует, после каждого промпта AI пересобирает билд, запускает/обновляет production-preview на localhost, проверяет ссылку и сообщает номер/время сборки. Показывается новый dist, а не устаревшая вкладка или только dev-server. До появления игры показываются подготовленные документы. Локальный preview не означает внешний deploy.

На checkpoint AI даёт ссылку, список изменений, скриншоты/видео и проверки, затем ждёт решения геймдизайнера. Согласованную версию фиксируют коммитом в GitHub-репозитории. Не надо останавливать каждую мелкую правку ради отдельного разрешения.

## Референсы и изменения

Скриншоты охватывают меню, каждую базовую механику, промежуточные действия, победу, награды и монетизацию. Подпись отвечает «что здесь происходит» и «что берём в нашу игру», для видео добавляется таймкод. AI дополняет подборку и выводит стиль в STYLE-GUIDE; сотрудник не дублирует это длинным художественным брифом.

PDF/видео — источники. Объём задачи задаёт геймдизайнер: чужая кампания на 100 уровней не становится автоматически заданием. После изменения требований обновляются STATUS и DECISIONS. Время автоматического прогона и время живого игрока хранятся отдельно.
