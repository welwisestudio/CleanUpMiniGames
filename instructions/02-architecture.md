# Архитектура новой игры

Это целевая архитектура шаблона. Исходный ASMR использует более тесно связанные `SpaApp`, сцены и установки методов в prototype; не нужно копировать эту связанность.

Концепцию и базовые механики определяет геймдизайнер. AI выбирает реализацию. Сменный платформенный интерфейс создаётся с dev-адаптером; настоящий адаптер YouTube и bootstrap подключаются в конце, после приёмки контента и финального баланса. Технические ID AI назначает сам, геймдизайнер называет уровни и описывает их.

## Рекомендуемые каталоги кода

```text
src/
  app/             bootstrap, переходы экранов, композиция сервисов
  core/            часы, события, pause reasons, случайность
  content/         конфиги игры, уровней, экономики, каталоги ассетов
  scenes/          BootScene, GameScene, UIScene
  mechanics/       независимые обработчики wipe, drag, memo и т. д.
  ui/              компоненты, layout, текст, модальные окна
  services/        SaveService, RewardService, AudioService, AssetService
  platform/        контракт, youtube/, dev/, будущие адаптеры
public/assets/     только используемые игровые файлы
reference/         входные референсы, masters, generation manifests
scripts/           подготовка ресурсов, сборка, упаковка
tests/             данные, контракты, ввод, layout, production
project/           заполненные документы и текущий статус
```

## Разделение ответственности

| Слой | Делает | Не делает |
|---|---|---|
| Content | Задаёт правила, координаты, ресурсы, цены, ID | Не вызывает рекламу и не пишет сохранения |
| Mechanics | Обрабатывает ввод и возвращает прогресс/завершение | Не решает, сколько монет начислить |
| Scenes | Создаёт объекты Phaser, отображает состояние | Не обращается к `ytgame` |
| UI | Показывает данные и отправляет намерения игрока | Не меняет баланс напрямую |
| App | Управляет состояниями, переходами и сервисами | Не рисует все механики в одном файле |
| Services | Валидирует сохранения, выдаёт награды, грузит ресурсы | Не зависит от конкретной рекламной сети |
| Platform | Переводит внутренний контракт в API площадки | Не знает цены предметов и правила уровней |

Строй простой явный поток вызовов. ECS, React, Redux, сервер и сложная шина событий не обязательны для небольшой Phaser-игры. Выделяй новый модуль по ответственности, а не ради числа папок.

## Данные и идентичность

```js
// Схема-пример, не готовый runtime.
const level = {
  id: 'garden-sort-01',
  mechanic: 'drag-sort',
  titleKey: 'levels.gardenSort',
  assetBundle: 'garden-sort',
  access: { type: 'campaign' },
  steps: [{ id: 'sort', targets: [], hint: { type: 'drag' } }]
};
const campaignOrder = ['garden-sort-01', 'memo-01'];
// Прогресс адресуется ID, не видимым номером карточки.
```

Порядок кампании, постоянный ID, имя уровня и номер в UI — разные вещи. Миграции изменяют схему данных с сохранением ранее заработанного доступа. Не удаляй прогресс при добавлении уровня или перестановке карточек.

## Состояния приложения

Минимальный набор: boot, loading, menu, playing, result. Модальное окно хранит точное состояние возврата. Дополнительные блокировки: userPause, hostPause, adBusy, navigationBusy, assetsLoading. Это независимые причины остановки, а не один переключатель `paused`.

Переход Next вычисляет следующий пункт кампании, затем маршрут: запустить, предложить доступ, перейти к бонусу, завершить кампанию. Закрытый уровень не должен вызывать молчаливый выход из обработчика. Возврат из настроек в меню не возобновляет прошлый уровень.

Для асинхронных действий используй токен запуска `runId`/`transitionId`. Поздний ответ рекламы или загрузки не применяется к уже другой стадии. Повторное нажатие блокируется до завершения перехода. При разрушении механики снимай события, таймеры, tweens, текстуры и физические тела.

## Сервисы

- SaveService: схема, миграции, load-before-write, последовательная очередь, dirty/error status.
- RewardService: проверка условий, уникальная операция, изменение состояния, запрос сохранения, событие для анимации.
- AudioService: единый mute gate и жизненный цикл музыки/SFX.
- AssetService: реестры menu/game/bundle, загрузка без дублей, retry, проверка отсутствующих файлов.

Для новой площадки меняется адаптер и bootstrap/build profile. Контрактные тесты, механики, таблицы экономики и UI остаются общими. Если платформа не поддерживает функцию, capability сообщает об этом честно; UI предлагает доступную альтернативу.
