# Как устроен исходный проект

Пути ниже относятся к ASMR, а не к ещё не созданной новой игре. Это карта чтения исходников. Если шаблон перенесён отдельно, сама ASMR-игра для работы по руководству не требуется.

`package.json` задаёт диапазоны Vite `^7.1.0` и Playwright `^1.55.0`; приведённые выше разрешённые версии взяты из package-lock. Python-инструменты не полностью описаны единым requirements-файлом — в новом проекте стоит это исправить. Нет оснований называть эту игру Unity-проектом, React-приложением, серверной экономикой или подключённой продуктовой аналитикой.

## Ключевые технические решения

**Материалы.** В базовых процедурах создаётся CanvasTexture `treatment`; действия меняют маску через canvas compositing, а progress вычисляется по сетке допустимых точек. В premium-очистке свои слои пыли, грязи, пены и стекла, ограниченные авторскими surface masks. Проценты и видимая очистка должны иметь общий геометрический смысл.

**Расширение сцен.** `installWorkshop`, `installPuzzles`, `installRomance`, `installPremiumScene`, `installHints` оборачивают методы `SpaScene.prototype`. Это ускоряло итерации, но порядок установки и базовые вызовы становятся скрытыми зависимостями. В универсальном шаблоне предложена явная композиция механик, а не дальнейшее копирование обёрток.

**Рендер.** Buffer соответствует физическим пикселям до DPR 2, `Phaser.Scale.NONE`, zoom обратно пропорционален DPR; `pixelArt:false` задан явно. Resize откладывается до PRE_STEP. Текстовые объекты имеют собственное повышенное разрешение. Границы HUD/игры/инструкций рассчитываются отдельно.

**Сохранения.** Сейчас `freshSave` имеет `version:3` и `levelOrderVersion:6`. Звёзды и ряд unlock-значений используют исторические индексы массива. Поэтому порядок меню вынесен в `LEVEL_ORDER`, а старые варианты сохранены для миграций. Для нового проекта проще хранить прогресс по постоянным строковым ID с самого начала.

**Облако.** `loadSave` сначала парсит строку и только затем разрешает записи через `acceptLoad`. `playables` сериализует записи, сохраняет последний pending snapshot, делает retry, откладывает score до записи. Вне платформы save не имеет постоянного browser storage.

**Награды.** Текущее состояние валюты отделено от `displayCoins` и очереди coin flights. Колесо/сундук фиксируют результат до показа. Это защищает от повторного начисления через перезапуск анимации, но не превращает клиентскую экономику в серверно-авторитетную.

**Загрузка.** Игра первоначально грузит menu subset; после выбора уровня грузит оставшийся полный набор. Повторные входы используют cache текущей сессии. Существуют retry и блокировка ввода во время загрузки.

**Физика.** Rescue использует Matter из поставки Phaser; не отдельную зависимость npm. Нарисованный штрих превращается в тело, взаимодействует с опорами; пчёлы давят на него при столкновении. Проверки физики включали 30/60/120 FPS согласно истории.

**Анимация.** Tweens, движение/масштаб спрайтов, compositing материалов, частицы и camera-like движение иллюстраций. Свадебные сцены — изображения с эффектами, не сгенерированные видеоролики или скелетная анимация. «Пиксар-стиль» в запросе не означает использование 3D-движка.

## Файлы производства

`reference/` хранит исходные генерации и manifests; `scripts/pack*.py` воспроизводят экспорт; `public/assets/` содержит runtime; `test-results/` — отчёты/снимки разных эпох; `dist/` — текущую сборку. Оптимизация работает только с dist, беря входы из public. `package-build.py` и `verify-package.py` контролируют имена и байты архива.

## Где документы отстали от кода

| Документ | Устаревшее описание | Что показывает текущий код |
|---|---|---|
| Начало README | 42 уровня, локальное сохранение, нет SDK | 58 уровней; cloud-only YouTube |
| Ранние VALIDATION / premium README | TEST AD / PreviewRewardedProvider | `YouTubeRewardedProvider` и адаптер Playables |

| BUILD-COMPRESSION | Stop выше 15 000 000 байт | Скрипт по умолчанию использует 20 000 000 |
| TEST-ADS | SDK failure даёт test reward | `ads.js` разрешает fallback только при `!playables.enabled` |
| YOUTUBE-PLAYABLES | Вне SDK объявления не имитируются | Local/dev/adtest при отсутствии SDK может дать test receipt |

Эти противоречия здесь обозначены; исходные документы игры в данной задаче не переписывались. В новом шаблоне единый STATUS и обновление документации входят в завершение каждого этапа.
