# Универсальный AI-шаблон производства 2D-игр

Версия 1.2 · 2 октября 2026 года. Основан на истории и коде Skincare ASMR; процесс уточнён по требованиям руководителя.

Это переносимая папка инструкций для AI и геймдизайнера. Готового движка, исходников игры, зависимостей и платных ассетов здесь нет. AI создаёт новый проект по заполненному брифу. Базовый стек — Phaser 3 + JavaScript + Vite, основная площадка — YouTube Playables. SDK подключается отдельным адаптером.

## Начать новую игру

1. Скопируйте всю эту папку в пустую папку новой игры, так, чтобы `AGENTS.md` лежал в её корне. Не работайте поверх старой ASMR-игры.
2. Откройте новую папку в AI-агенте с доступом к файлам, терминалу и браузеру.
3. Подключите GitHub-репозиторий. Подготовьте свои Core Loop, механики, первые уровни, монетизацию, видео и много скриншотов с подписями; сохраните в `reference/input/`. Заполните [короткий бриф](templates/PROJECT-BRIEF.md).
4. Отправьте стартовый промпт из [руководства сотрудника DOCX](EMPLOYEE-GUIDE.docx): он включает Higgsfield MCP `https://mcp.higgsfield.ai/mcp`. Графика всегда генерируется в Nano Banana 2; фон у спрайтов удаляется отдельной операцией Higgsfield Background Remover через MCP. Доступность операции проверяется при подключении.
5. Двигайтесь по этапам руководства. После каждого этапа проверяйте игру сами и сохраняйте результат приёмки.

Для AI первая точка входа — [AGENTS.md](AGENTS.md). Человеку достаточно [EMPLOYEE-GUIDE.docx](EMPLOYEE-GUIDE.docx); [Markdown-копия](EMPLOYEE-GUIDE.md) синхронизирована с ним. Если агент не читает AGENTS.md автоматически, прямо попросите прочитать его.

Геймдизайнер задаёт концепцию; AI уточняет, реализует и после приёмки основы масштабирует контент. Каждый результат уже существующей игры показывается свежим билдом на localhost. Checkpoints: концепция → один уровень → его визуал/фидбек → пять уровней и UI → метаигра → весь контент со звуком → баланс → релиз. YouTube SDK интегрируется в конце, после баланса; сменный интерфейс с dev-адаптером предусмотрен заранее.

## Что универсально, а что выбирается для каждой игры

Универсальны разделение данных и механик, слой платформы, правила сохранений, приёмка, адаптивность и воспроизводимая сборка. Жанр, палитра, число уровней, цены, длительности, награды и необходимость физики задаются брифом. Рисованный UI нужен, когда он соответствует утверждённому стилю; ASMR-палитра и свадебные истории не являются стандартом для всех игр.

Сначала сделайте один полностью законченный уровень с качественным UI и фидбеком, затем первую небольшую подборку уровней. Массовая генерация начинается после приёмки образца. В исходном проекте поздняя переделка UI и всех VIP-уровней потребовала повторной работы; шаблон переносит эту проверку на начало.

## Статус материалов

Рекомендованная архитектура в этой папке — улучшенный шаблон для новых проектов, а не утверждение, что ASMR уже устроен точно так же. Исторические тесты ASMR не означают проверку новой игры. Документы платформы нужно сверять с официальными требованиями перед каждой публикацией.

Не копируйте в новый проект `node_modules`, `dist`, чаты, `.env`, старые сохранения, account/project IDs и весь арт ASMR. Исходные документы YouTube сохранены для справки; Unity-инструкции из них не применяются к Phaser.
